# Rename: Bilingual Meeting Captions → Twinscript 会意

**Date:** 2026-08-02

**English name:** Twinscript — the two writing systems the app puts side by side.
Latin and Han script are also literally what the caption router classifies
(`classifyScript` in `electron/captions/caption-domain.js`).

**Chinese name:** 会意 (huìyì) — "to grasp the meaning," with the flavour of
understanding without it needing to be spelled out. It is also 会意字, one of the
six classical categories of Chinese character formation, so it echoes
"Twinscript" rather than merely translating it.

## Where each name appears

| Surface | Value |
| --- | --- |
| Product / display name | `Twinscript` |
| npm package, executable, kebab id | `twinscript` |
| Squirrel package name | `Twinscript` |
| Squirrel executable | `twinscript.exe` |
| AppUserModelID | `com.squirrel.Twinscript.twinscript` |
| macOS bundle id / Forge appId | `com.jiyu.twinscript` |
| Virtual camera friendly name | `Twinscript` → enumerates as `Twinscript (Windows Virtual Camera)` |
| Camera source DLL | `twinscript-vcam-source.dll` |
| C++ namespace | `twinscript::vcam` |
| Native camera env vars | `TWINSCRIPT_VCAM_REGION_PATH`, `TWINSCRIPT_VCAM_SYNTHETIC` |
| Health pipe | `\\.\pipe\twinscript-camera-<uuid>` |
| Operator UI header | `TWINSCRIPT 会意` |

会意 appears only in the operator UI, deliberately. The audience overlays and the
camera stage stay free of branding — [`virtual-camera.md`](virtual-camera.md)
requires "no control buttons, cursor, API state, cost, or settings in the feed."

## Deliberately NOT renamed

- **The camera CLSID `{6B8F2C4A-9D3E-4A17-8C25-1E7B4F6D9A03}`.** It must never
  change: a new CLSID orphans any previously registered camera. The friendly name
  is free to change; the identity is not.
- **Descriptive uses of the word "bilingual"** in prose, comments, and tests.
  One of these is load-bearing: `live-transcription-session.js` sends the
  transcriber a prompt describing "a bilingual English and Simplified Chinese
  engineering meeting…". That is content, not branding — renaming it would have
  degraded recognition accuracy.
- ~~**The GitHub repository** `imperator28/bilingualmeetingcaption`, including the
  `iconUrl` in `forge.config.js` that points at it. Renaming the repo is a
  GitHub-side action; the icon URL must be updated in the same change if you
  do.~~ **Done on 2026-08-09:** the repository is now
  `imperator28/Twinscript`. The `iconUrl`, the clone command in
  `developer-setup.md`, the `Repository:` line in `windows/README.md`, and the
  two prose references in `implementation-guide.md` and `validation-matrix.md`
  were updated in the same commit, and the `origin` remote was repointed.
  GitHub redirects the old path, so nothing broke in the interim - which is
  exactly why a stale URL here could have gone unnoticed indefinitely.
  `raw.githubusercontent.com` is the one that does not reliably redirect, and it
  is what Add/Remove Programs fetches the installer icon from.
- **`.worktrees/` and `.claude/`** — gitignored checkouts of other branches. They
  keep the old name until those branches are rebased or merged.

## Migration consequences

Nothing here needs action for a fresh install, but each is a real behaviour change:

1. **User data moves.** `app.setName()` drives Electron's `userData` path, so
   settings and the encrypted API key move from
   `%APPDATA%\Bilingual Meeting Captions\` to `%APPDATA%\Twinscript\`. An
   existing saved key and `caption-settings.json` are effectively orphaned — the
   app will start with defaults and prompt for the key again. Only test-install
   data existed at rename time.
2. **The meeting-records folder moves** from `Documents\Bilingual Meeting Captions`
   to `Documents\Twinscript`. Existing records are not migrated. No real
   transcripts existed at rename time; add a migration if that changes before
   first release.
3. **macOS Keychain entries change** — the credential store derives its service
   name from the product name, so `Bilingual Meeting Captions Safe Storage`
   becomes `Twinscript Safe Storage`. The old entry is left behind, harmless.
4. **Squirrel treats this as a different application.** The package name changed,
   so an installed old build will not upgrade to Twinscript; it becomes a second
   entry in Add/Remove Programs. Uninstall the old one manually.
5. **The native camera registration points at the old DLL name.** Any existing
   HKLM/HKCU registration references `bilingual-vcam-source.dll`, which no longer
   exists. Unregister and re-register after rebuilding — see
   [`evidence/2026-07-31-w4-media-source/README.md`](evidence/2026-07-31-w4-media-source/README.md)
   for the exact commands.
